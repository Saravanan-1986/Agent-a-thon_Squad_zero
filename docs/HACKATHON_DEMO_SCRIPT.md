# 🏆 Knowledge Debt Engine — Hackathon Demo Script & Judge Playbook

> **The Non-Negotiable Core Principle:**  
> *"LLM proposes. Human mentor reviews. Empirical evidence decides."*

## ⚡ 1. The 30-Second Elevator Pitch

> *"Every learning platform does the same thing: when a student fails a Linked Lists question, it says 'Wrong answer, here is an explanation for Linked Lists.'*  
>  
> *That’s treating the symptom. In software engineering, when a bug appears downstream, you don't patch the surface—you trace the technical debt to its root cause.*  
>  
> *The **Knowledge Debt Engine** is a graph-native, stateful multi-agent system that treats learning gaps like technical debt. By traversing a 49-concept prerequisite DAG, our Recursive Diagnosis Agent discovers that the student actually failed Linked Lists because of unresolved debt in **Pointer Dereferencing**. When passive explanations fail, our system dynamically adapts to an interactive RAM memory simulation. And most importantly: **mastery can never be self-reported or generated by an LLM—only fresh empirical evidence can retire the debt**."*

## 🛠 3. Technical Architecture Highlights

| Component | Technical Implementation | Why it Beats Competitors |
| :--- | :--- | :--- |
| **Prerequisite DAG** | 49 concepts, 41 directional prerequisite edges, SQLite relational graph | Traverses multi-hop causal chains instead of surface keyword matching |
| **Recursive Diagnosis** | Multi-hop graph traversal with upstream debt aggregation | Finds the *root cause* (Memory Model / Pointers), not just symptoms |
| **Multi-Agent Engine** | Diagnosis Agent + Intervention Agent + Verification Agent | Clear separation of concerns with structured JSON schema outputs |
| **AI Integration** | Google Gemini (`gemini-flash-lite-latest`) with token caps & zero-crash fallback | Sub-second latency, strictly budget-conscious, zero-crash reliability |
| **State Machine Guard** | Strict 10-state deterministic finite state machine (FSM) | Eliminates hallucinations; invalid transitions strictly forbidden |
| **RAM Visualizer** | React interactive memory model with stack frames and hex addresses | Replaces static slides with dynamic interactive conceptual scaffolding |

## 💡 4. Handling Judge Q&A Like a Pro

### **Q: "Why not just use RAG / Vector Search over a textbook?"**
> **Answer:**  
> *"Vector search is similarity-based. If a student fails a question containing the words 'Linked List', vector embeddings will retrieve more Linked List documents. But conceptual dependencies are causal and directional, not semantic. You cannot understand Linked Lists without Pointer Dereferencing, and you cannot understand Pointers without the RAM Memory Model. A DAG captures causality; vector search only captures proximity."*

### **Q: "What prevents the LLM from hallucinating that a student passed?"**
> **Answer:**  
> *"Our architectural separation of powers: the LLM never has write access to the state column in our database. The state machine is pure Python/SQL. The only function that can transition a debt to `REPAID` is `update_debt_status()`, which strictly asserts that `evidence.score >= 70%` on an unseen transfer question. The LLM evaluates the answer, but the deterministic state machine gates the database."*

### **Q: "How does this scale to other subjects like Physics or Medicine?"**
> **Answer:**  
> *"The Knowledge Debt Engine is domain-agnostic. We proved this by testing with both DBMS and DSA curricula. Any domain with prerequisite structures (calculus, organic chemistry, clinical medicine) can be modeled as a DAG. Our dataset importer validates and loads concepts, prerequisites, and question banks automatically."*
